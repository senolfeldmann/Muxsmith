# Plan 5.6 design decisions

Plan 5.6 is the pre-1.0 idiomacy fix wave: mechanical idiom/dup/yagni/stdlib
cleanups plus one deliberate wire-format extension. That extension is the only
decision the wave records; every other change is a behavior-preserving refactor
grounded in the idiomacy-review findings, not a design choice.

## D36: OverlappingRules claimants carried structurally, not re-parsed

**Decision (Plan 5.6, T2):** the claimant rule indices of an `OverlappingRules`
diagnostic are carried as a structural `Diagnostic.claimants: Vec<usize>`
field, set at the single production site from the same `rules` slice that
renders the human-readable `rules` display param. One builder,
`Diagnostic::with_claimants`, populates both the structural field and the
display param, so they cannot diverge. The suggestion engine's
`overlap_conflicts` reads `d.claimants.clone()` directly instead of splitting
and re-parsing the rendered `"tracks[0], tracks[1]"` string back into indices.

**Rationale:** the D33 symmetric-narrowing path depends on recovering every
claimant of an overlap to generate narrowing candidates for each. Recovering
them by re-parsing the rendered display param couples a load-bearing
control-flow input to a presentation string: any change to how the `rules`
param is formatted (a different separator, an added prefix, a rendering shift)
would silently break symmetric suggestion generation with no compile-time
signal, failing only if a test happened to exercise the exact overlap shape. A
structural field is the data the engine actually needs; the display string
becomes a pure rendering of the same source, so the two cannot drift. Aligns
with core-37 (core emits codes + structured params; formatting is the
renderer's concern) and with explicit-over-magic.

**Rejected alternatives:**
- Keep re-parsing the rendered `rules` param. Rejected: it is exactly the
  display-format coupling that makes the D33 path fragile - zero structural cost
  saved for a standing correctness hazard.
- Pin the `rules` param to a shared format constant and parse against it.
  Rejected: it adds a constant and a parser both sides must honor, still
  round-trips machine data through a human string, and leaves the invariant
  enforced by convention rather than by construction. The structural field
  removes the round-trip entirely.

**Interface/wire changes (doctrine §2):** `Diagnostic` gains a public
`claimants: Vec<usize>` field, attributed
`#[serde(default, skip_serializing_if = "Vec::is_empty")]`. The batch/config/run
JSON reports (spec 7) therefore gain a `claimants` array on `overlapping-rules`
diagnostics only; the field is empty and omitted for every other code via
`skip_serializing_if`, so no other diagnostic's JSON changes. No new DiagCode
and no Fluent-catalog change - the `rules` display param the renderer keys on
is byte-identical. `Diagnostic` is `Serialize`-only, so `default` is inert
today; it is kept for symmetry with the skip attribute and against a future
`Deserialize`.
