## D32: UnknownPropertySkew mitigation - explicit `raw:` opt-in (shape B)

**Decision (Şenol 2026-07-11):** unknown property names stay hard-rejected at
config time UNLESS marked with a `raw:` prefix. A `raw:`-prefixed property is
matchable untyped; config-time emits `RawProperty` (info; the visible escape
valve) and, on a known-special property (`language`, `codec_kind`),
`RawOnKnownProperty` (warning: bypasses normalization, byte-literal match).
Plan time revives `UnknownPropertySkew` (warning) per consumed `raw:`
property, params `found_version`/`pinned`, covering both genuine newer-schema
skew and same-version untyped matching. Spec §9.2 is amended by T16 to
exactly this semantics (self-contradiction sweep after).

**Rationale:** a static in-profile opt-in is the only disambiguator that
survives spec 5.5's "dry-run is a superset of validate" invariant while
keeping the config-time typo hard-reject intact and making §9.2 reachable and
honestly typed. Aligns with explicit-over-magic and with the SI-3 finding.

**Marked assumption (unopposed at decision):** `RawProperty` (info) is KEPT,
not dropped per the minimal variant - the escape valve must be visible at
validate; a silent bypass undercuts the point of B over C.

**Rejected alternatives:**
- Shape A (did-you-mean + formally drop the §9.2 promise): correct cleaner
  downgrade if forward-compat-without-a-release is YAGNI; rejected because
  the §9.2 promise is kept deliberately.
- Shape C (warning-only downgrade): rejected outright - guts typo protection
  unconditionally, including on non-skewed mkvmerge (the C-4 case), and opens
  the optional-rule and not:-inversion silent holes (C-2/C-3).

**SI-3 parity:** mkvtoolnix-gui preserves unknown `-J` properties untyped in
a generic QVariantMap (src/mkvtoolnix-gui/merge/track.h:24, assigned
util/file_identifier.cpp:310) and ignores identification_format_version
(schema constant ID_JSON_FORMAT_VERSION = 20, src/merge/id_result.h:37), but
has no match-by-property-name surface - its permissiveness at the data layer
gives no cover for implicit untyped matching at Muxsmith's rule layer.
Classification: justified divergence (explicit gate where mkvtoolnix has no
comparable surface).

**Interface/wire changes (doctrine §2):** new DiagCodes `RawProperty` (info,
config-time), `RawOnKnownProperty` (warning, config-time); `UnknownPropertySkew`
gains params `found_version`, `pinned` and becomes emitted (was dead). All
three carry C1 exhaustive-fixture obligations in catalog_completeness.

**Implementation facts for T16 (from the analysis):** the matcher already
compares untyped (parse_track keeps every scalar, identify.rs:200-222);
UnknownPropertySkew is currently emitted nowhere; the whole change is a
validate.rs decision plus plan-time emission.

## D33: OverlappingRules auto-suggestions - symmetric, acceptance-filtered (policy 3)

**Decision (Şenol 2026-07-11):** generate narrowing candidates for ALL overlap
claimants symmetrically; the existing acceptance criterion
(`resolves_without_regression`, gated on the target overlap INSTANCE
disappearing) selects the feasible ones - exactly as the AmbiguousRule path
already works. NOT-polarity candidates seeded from the shared track's own
property vector. Rank tiebreak between surviving narrowings on different
rules: broader rule first, then lower rule index. Reuses
candidates_for_rule / resolves_without_regression / partition_for_rule; no
new edit variant, no new selection mechanism, no new DiagCode.

**Rationale:** feasibility (a rule's `optional` flag / batch structure), not
a precedence guess, determines which rule can be narrowed; letting the
existing acceptance criterion select is both most correct and most
consistent with the engine.

**Tradeoff (accepted):** the common case - two required rules colliding on
one track in one file - yields NO suggestion, only the explicit
no-fix/partition report. Honest, and an unavoidable property of the
narrow-only v1 grammar (a narrowing can only zero a claimant's match, never
redirect it; every claimant matched exactly one track at emission).

**Technically forced (recorded as forced, not taste):** seed from the shared
track's property vector; acceptance gates on the overlap instance
disappearing; >=3 claimants cannot be resolved by a single narrowing (falls
to the partition report, which names ALL claimants - ties to the ROADMAP
diagnostics-polish item (i)); the two-required-single-file case has no v1
suggestion.

**Marked assumptions (unopposed at decision):** symmetric selection (the
decided option); tiebreak broader-then-index; NOT-polarity as the seed
polarity; narrowing an optional rule to empty is a first-class suggestion;
the unresolvable-overlap report wording is left to the implementer within
the existing catalog voice.

**Rejected alternatives:** later-by-list-order and broader-by-domain
precedence policies - both guess intent and propose infeasible narrowings
the acceptance criterion would have to reject anyway; kept only as the
deterministic rank tiebreak.

## Memo residues (from Plan 5.5 reviews)

- **D6 partition-key wording superseded:** D6's "conflict-signature multiset"
  grouping key is superseded by suggestion-keyed grouping (T13), RATIFIED via
  spec §5.3:282 - the spec mandates the outcome ("list the files requiring
  different resolutions"), not a key; suggestion-keying is the more literal
  reading, and the property-vector key could over-report by splitting files
  that share a resolution.
- **EmptyPlan divergence (T6, SI-3):** mkvtoolnix-gui has NO general
  zero-selected-tracks warning (tab.cpp:489-522 is audio-only, opt-out,
  confirm-dialog; isReadyForMerging never checks total selection) and
  mkvmerge exits 0 writing the empty file. Muxsmith's unconditional per-file
  EmptyPlan warning is a DELIBERATE DIVERGENCE: an interactive GUI shows the
  selection state by construction, a declarative batch tool must say it.
