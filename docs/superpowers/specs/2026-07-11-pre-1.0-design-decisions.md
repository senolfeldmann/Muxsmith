# Pre-1.0 design decisions (non-code gates)

Decisions taken while resolving the pre-1.0 non-code gates (ROADMAP). Same
format as the per-plan design-decision memos; numbering continues after
D32/D33, which are reserved by Plan 5.5's design-gated packages.

## D34: Production CSP - strict explicit-directive block (2026-07-11)

**Decision.** `app.security.csp` in tauri.conf.json is set to the strict
object-form block:

```json
"csp": {
  "default-src": "'none'",
  "script-src": "'self'",
  "style-src": "'self'",
  "img-src": "'self'",
  "connect-src": "ipc: http://ipc.localhost",
  "base-uri": "'none'",
  "form-action": "'none'"
}
```

No `devCsp`. No `dangerousDisableAssetCspModification` (Tauri's automatic
nonce/hash injection for its IPC bootstrap stays on; that is why
`script-src 'self'` suffices without manual nonce handling).

**Rationale.** The measured frontend surface (full scan 2026-07-11,
spot-verified): no remote resources of any kind, no fetch/WebSocket/XHR,
Fluent catalogs inlined at build time, SFC styles extracted to one external
CSS file, no `v-html`/`innerHTML`/dynamic script-or-style injection, no
asset protocol, no `:style` bindings, built index.html carries only the two
external asset references. `'self'`-only is therefore the true surface, not
an approximation. The strict `default-src 'none'` base makes every future
surface addition (first bundled font, worker, media) a conscious CSP edit
instead of a silent allowance - explicit over magic. Untrusted strings
(filenames, mkvmerge output, profile YAML) reach the DOM only through Vue
text interpolation, so the CSP is pure defense-in-depth; at this surface it
costs nothing.

**Rejected alternatives.**

- *Docs-idiom baseline* `default-src 'self'; connect-src ipc:
  http://ipc.localhost` (string form): defensible and common in
  well-maintained Tauri apps, but silently allows bundle-origin loads for
  every unenumerated directive (media/font/worker/manifest).
- *A `devCsp` block* (initially proposed, withdrawn same day):
  source-verified against tauri 2.11.5 (manager/mod.rs:369 selects
  dev_csp-or-csp, but the only application sites are the `tauri://`
  protocol handler for embedded production assets, manager/mod.rs:440, and
  data-URL webviews). With `devUrl` set - our standard Vite dev flow -
  neither `csp` nor `devCsp` ever reaches the dev page, so the block would
  be dead config. Corollaries: dev/HMR is unaffected by any CSP setting
  here, and CSP verification must exercise a production build, not
  `tauri dev`.
- *`csp: null`* (create-tauri-app scaffold default, the status quo): no
  blast-radius cap if an injection path ever appears (a future `v-html`, a
  dependency regression).

**Triggers created.** None. A future blocked surface addition fails visibly
at the CSP during development of that feature; that visible failure is the
designed behavior, not a deferred action.

**Interface/wire-format changes.** None.

**mkvtoolnix parity (SI-3).** Not meaningful for this decision - a Qt
application has no CSP equivalent. Recorded as a non-comparison.
