# Plan 5.7 decisions

## D37: DiagCode::NonUtf8Path - reject non-UTF-8 argv-bound paths at plan finalize

**Decision:** paths that would enter the mkvmerge argv (output path, donor
and source paths, group/global argument paths) are validated with
`to_str()` during the core planner's finalize pass. A failure emits a new
error-severity diagnostic `DiagCode::NonUtf8Path` (params: lossy path
rendering, role of the path) once per offending file, and that file's plan
is dropped. No job is ever built from a lossily-converted path.

**Rationale:** `Path::display().to_string()` replaces invalid bytes with
U+FFFD, so a non-UTF-8 output or donor path silently corrupts the
mkvmerge command line instead of erroring (routed-items verdict item 2).
The identify path already rejects non-UTF-8 input paths explicitly
(runtime.rs:206, Parse error) - the command-building side gets the same
contract. Muxsmith is declarative batch: a profile row that cannot be
executed faithfully must fail loudly at plan time, not mutate silently at
exec time.

**Rejected alternatives:**
- Status quo (silent U+FFFD substitution): corrupts commands; violates
  the fail-loud planning contract; rejected.
- Plumbing `OsString` through the command layer end to end: preserves
  arbitrary bytes but forces OsString across the argv assembly, JSON
  report surface (which is UTF-8 by construction), and every test
  fixture, for a case the identify path already rejects at ingest on
  the input side. Cost out of proportion; rejected.
- Rejecting at profile validate instead of finalize: donor/source paths
  are only fully known after resolution; finalize is the single point
  where every argv-bound path exists. Rejected as incomplete.

**Interface/wire-format change:** new `DiagCode::NonUtf8Path` value in
the diagnostics JSON surface (code + params `path` (lossy) + `role`);
bilingual catalog entries; spec section 5.2 gains its row. No existing
code's shape changes.

**Triggers created:** none.

**Consistency note:** mkvtoolnix comparison (SI-3): mkvmerge itself takes
whatever bytes the shell hands it; the divergence is deliberate and
recorded - Muxsmith's command assembly is String-based by design (JSON
report parity), so the boundary must reject what it cannot represent,
matching the existing identify-side rule rather than mkvmerge's
byte-transparent CLI.
