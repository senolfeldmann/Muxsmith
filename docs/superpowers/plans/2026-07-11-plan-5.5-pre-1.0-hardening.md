# Plan 5.5: Pre-1.0 Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close every pre-1.0 gate decided in the 2026-07-11 sweep walkthrough: spec-vs-code gaps, silent-failure channels, robustness holes, diagnostics polish, the German locale, and the CI/test infrastructure that proves it all on three OSes.

**Architecture:** No new subsystems. Every task hardens an existing seam: planner/validate (silent-failure channels), executor (stream + thread robustness), CLI rendering (voice for empty/zero cases, snapshot locks), capability layer (wire the built-but-unconsumed validators), i18n (plural selectors, key parity, de catalogs), CI (real mkvmerge on all three legs, ninth gate part). Four packages open with their own design round producing a D-memo before code.

**Tech Stack:** Rust workspace (pinned 1.96.1), proptest + insta (new dev-deps, spec-§10-mandated), Fluent i18n, Tauri 2/Vue 3 GUI (touched only by message keys), GitHub Actions (SHA-pinned).

**Provenance:** Every task cites its sweep-walkthrough decision number (#N) or residue round (R1/R3). Full context: docs/ROADMAP.md pre-1.0 gates section + the process-learnings distillate in Şenol's Nextcloud project folder. Decision numbers D32+ are free.

**Style note (documented deviation from the plan-1-3 transcription style):** tasks are anchor-precise specs (exact files, line anchors verified 2026-07-11, named tests with concrete assertions; full code where it was read during the audit), not full-code transcriptions - four packages are design-gated and implementers run TDD themselves. Şenol approved the plan being written in this style; if a task feels underspecified to an implementer, that is a DONE-blocking question, not a license to guess.

Current verified code:

```rust
fn next_line(&mut self) -> Option<String> {
    let mut line = String::new();
    match self.reader.read_line(&mut line) {
        Ok(0) | Err(_) => None,
        Ok(_) => Some(line.trim_end().to_string()),
    }
}
```

- [ ] Step 1: Failing test: feed a reader whose stream contains `b"ok line\n\xFF\xFE broken\nafter\n"` through a `LiveJob`-shaped harness (extract the read logic into a testable `fn read_next_line<R: BufRead>(r: &mut R) -> Option<String>` if needed - keep `next_line` a thin delegate).
