## What was implemented

1. **`crates/muxsmith-core/src/capability/mod.rs`**: added a documented
   public accessor `matchable_properties()` beside `matchable_type`,
   returning `generated::MATCHABLE_PROPERTIES` (`&'static [(&'static str,
   PropType)]`). `mod generated` stays private (`mod.rs:9`, no `pub`); the
   accessor is the only new surface. Rustdoc explains what it returns, why
   it exists (the `ts` feature's emitter needs the table from outside the
   crate), and cross-references `matchable_type` for the `codec_kind`
   caveat (the virtual is not in this table).

2. **`crates/muxsmith-core/tests/ts_export.rs`**: added
   `use muxsmith_core::capability::{PropType, SETTABLE,
   matchable_properties, matchable_type};`, a private `fn scalar_tag(t:
   PropType) -> &'static str` (exhaustive 4-arm match, no wildcard arm: a
   fifth `PropType` variant fails the Rust build), and a second `#[test]
   fn emit_settables_ts()` mirroring `emit_keywords_ts`'s structure. It
   writes `src/bindings/settables.ts` containing: a `// @generated by ...`
   header, `export type PropScalarType = "boolean" | "integer" | "float" |
   "string";`, then `SETTABLE_TYPES` (iterating `SETTABLE` directly) and
   `MATCHABLE_TYPES` (iterating `matchable_properties()` in declaration
   order, then appending a final `"codec_kind"` row whose tag is derived
   via `scalar_tag(matchable_type("codec_kind").unwrap())`, never
   re-asserted). Both tables are typed `as const satisfies
   Record<string, PropScalarType>` with quoted keys. No property name or
   type tag is hand-mirrored anywhere in this file; every row comes from a
   core-crate source (`SETTABLE`, `matchable_properties()`,
   `matchable_type("codec_kind")`).

3. **`src/bindings/settables.ts`** (created, committed, generated):
   79 lines, both tables plus the shared union type. Content verified
   below.
