## Decisions made (and why)

- Strict independent uniqueness for track rules -> Şenol wants maximal explicitness; ambiguity is an error; error quality + suggestion engine compensate. Do not relitigate ordered-consumption.
- Suggestion engine contract -> suggestions are simulated against the WHOLE batch and only emitted if they resolve every instance without new conflicts anywhere ("an applied suggestion survives the next dry run"). Suggestions are structured edits, not prose.
- Full MKV-structure control in v1 (attachments/chapters/tags/title) -> his scope call. Attachments are NOT uniqueness-constrained (first-matching-rule-wins, `unmatched: keep`).
- Stack Tauri 2 + Rust core + React/TS, MIT license -> settled after alternatives (Wails v3 alpha, Avalonia) were weighed.
- Capability model: matchable properties generated at build time from the mkvmerge identification schema (v20) by `crates/xtask` into committed `generated.rs`; schema never vendored. Runtime version skew -> `UnknownPropertySkew` warning, untyped matching.
- `UnknownProperty` = config-time error for match conditions; changes use `UnknownSettableProperty` (spec 5.2 amended to match code).
- Model detail: untagged config enums use newtype block variants (`FilenameCfg::Template(TemplateBlock)`, `SourceCfg::External(ExternalBlock)`) because serde ignores `deny_unknown_fields` on inline struct variants.
- YAML crate is `yaml_serde` 0.10.x (maintained fork; serde_yaml is archived).
- Identification cache (Plan 2): in-memory per session, keyed path+mtime+size; run re-plans before executing (dry run never stale). On-disk cache deferred.
