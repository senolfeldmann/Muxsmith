Green state reachable in both (all present, untampered, `--ignore-missing` ->
three OK lines, exit 0), so the exit-1 results are a firing check and not a
command that always fails.

**The flag is genuinely parsed, not silently ignored.** Misspelt as
`--ignore-mising` both implementations reject it: `sha256sum: unrecognized
option '--ignore-mising'` and `Unknown option: ignore-mising`. Mechanism, at
the source: `shasum` line 281 is `next if $ignore_missing && ! -e $fname;` -
the skip is conditioned on non-existence alone, so a present file reaches the
comparison unchanged. The runs above are the evidence; the line is the
explanation.

One control was initially unfaithful and is reported rather than buried: my
first shim returned `undef` for a missing file, while the real `Digest::SHA`
dies and `shasum`'s `sumfile()` catches that with `eval {}`. Control H
therefore crashed at `hexdigest` instead of printing `FAILED open or read`.
The shim was corrected to die; H then reproduced the documented shape. The
`--ignore-missing` controls were unaffected either way.
