## D14 - soft fail-fast

13. **--fail-fast semantics | soft (stop dequeuing, in-flight finish, queued->Cancelled)** - pattern/executor/decided/memo D14. "On the first Failed job, the queue dequeues nothing further; already-running jobs finish; jobs still queued become Cancelled." Steelman for the losing hard variant: a hard-kill would stop wasted work sooner on systemic failures.
14. **--fail-fast semantics | soft** - pattern/executor/reinforced/task-3-review-verdict.md. `soft_fail_fast_cancels_queued_but_not_inflight` asserts `[Failed,Cancelled,Cancelled]`, exactly one Started AND `fake.spawned().len()==1` (genuinely pins "dequeue nothing further").
15. **Batch failure default | hard-kill on first failure** - restraint/executor/decided/memo D14. Rejected as default. Steelman: systemic failures (disk full) - hard-kill stops the siblings immediately. Losing argument: mkvtoolnix-gui has NO fail-fast (`Model::onStatusChanged` treats Failed like any terminal state, model.cpp:337-380); make/cargo/GNU-parallel `--halt soon,fail=1` all stop scheduling and let running jobs finish. Kill+delete-partial stays reserved for the two unambiguous intents (mkvmerge error, user cancel).
16. **--fail-fast=now (kill in-flight, GNU-parallel now,fail=1 analog)** - non-decision/executor/deferred/memo D14. blocked_on: external (real usage demand). "Considered and deferred: a --fail-fast=now value ... as an additive v1.x flag if real usage asks for it."

## D17 - delete partials (deliberate divergence from mkvtoolnix-gui)

39. **Partial outputs | deleted on mkvmerge error (exit 2) and on cancel** - pattern/executor/decided/memo D17. Deliberate divergence from mkvtoolnix-gui (which keeps partials by default, `m_removeOutputFileOnJobFailure` off, settings.cpp:621). Steelman for the GUI's keep default: it is interactive, the user sees the red job and a partial aids diagnosis. Losing to Muxsmith's bulk contract ("a file in the output tree is a valid output"); sharpest argument: with on_collision:skip a kept partial makes the rerun skip the broken file as already done - a silent-corruption footgun.
40. **Partial outputs | delete on failure/cancel** - pattern/executor/reinforced/task-2-review-verdict.md. `exit_two_is_failed_and_partial_deleted` and `killed_under_cancel_is_cancelled_and_partial_deleted` drive `run_job` through a real tempdir and assert the partial is gone.
41. **delete-partial scope | never delete when the process never ran (spawn-failure over-deletion)** - pattern/executor/violated-corrected/task-2-review-verdict.md + commit f394f61. Spawn failure routed through delete-partial, silently destroying a pre-existing valid output under overwrite semantics; fix assembles the Err-arm outcome inline (Failed, exit None, errors:[msg]) without reaching the deleting `finish`. Pinned by `spawn_failure_is_failed_but_keeps_preexisting_output` (RED against pre-fix code).
42. **killed-job wait() contract | must return None cross-platform (Windows kill broke D17 where D16 mattered)** - pattern/executor/violated-corrected/whole-branch-review-verdict.md + commit 75c075f. Windows `Child::kill` is `TerminateProcess(h,1)` and `ExitStatus::code()` is always Some, so a killed job mapped Some(1)->Warning->partial kept, never Cancelled. Fix: shared `Arc<AtomicBool>` killed flag set before `kill()`; `wait()` folds through pure `resolve_wait` returning None when set (mirrors FakeJob).
